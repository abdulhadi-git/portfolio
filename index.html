E-commerce Store: a streamlined online shopping experience

I built a single-vendor e-commerce store with product browsing, cart management, checkout, and order confirmation. The admin panel makes it easier to manage products and orders, bringing essential online shopping operations into one place.

The challenge

I wanted to build an online store that covers the whole buying journey, not just a list of products. Visitors should be able to browse, fill a cart and check out without friction, while the store owner needs one place to manage products and orders. The hard part was keeping cart, checkout and order data consistent from one step to the next.

What I built

A single-vendor store built with Laravel and MySQL. Visitors browse products, add them to a cart, check out and receive an order confirmation. Behind it sits an admin panel where the owner adds and edits products and follows every order. The interface is plain HTML, CSS and JavaScript, so pages stay light and easy to change.

The result

  • Complete shopping flow from browsing to order confirmation, working end to end
  • One admin panel for products, orders and day-to-day store operations
  • What I learned how carts, checkout and orders fit together in a Laravel application

Chatify: real-time messaging built for seamless conversations

I built a real-time chat application featuring private and group messaging, file sharing, online status, and read receipts. Using WebSockets, I implemented instant message updates to make conversations more interactive and responsive.

The challenge

A normal page can only show new data when you ask for it, so it cannot push a message to someone else's screen. I wanted to learn how chat apps feel instant, and then build one. On top of sending text, the app had to handle group conversations, file sharing, who is online and whether a message has been read.

What I built

Chatify is a real-time chat app on Laravel. Laravel Reverb runs the WebSocket server and Laravel Echo listens for events in the browser, so new messages, online status and read receipts appear without a refresh. Users can chat privately or in groups, share files, and confirm their email when they sign up. MySQL stores users, conversations and messages.

The result

  • No page refresh messages, online status and read receipts update live
  • Private and group chat with file sharing and email verification
  • What I learned how events, WebSockets and Echo work together in Laravel

Library Desk: a streamlined library management system

I built a library management system with book and category management, member records, book issuing and returns, and overdue fine tracking. An admin panel helps manage borrowing records, monitor book availability, and keep library operations organized.

The challenge

A library depends on records that all point at each other: books, categories, members and every borrowing. I wanted to build a system that keeps that data accurate, so staff can always see which books are available, who has borrowed what, and which returns are late. Keeping track of overdue fines was a key part of the problem.

What I built

Library Desk is a Laravel app running on SQL Server. Staff manage books and categories, register members, issue books and record returns. The admin panel shows borrowing records and book availability, and overdue returns carry a fine so nothing slips through. HTML, CSS and JavaScript handle the interface.

The result

  • Full borrowing cycle issue, return and overdue fines in one system
  • One admin panel for books, members and borrowing records
  • What I learned how to design a database where books, members and loans depend on each other
